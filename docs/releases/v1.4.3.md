# XGDTool v1.4.3 — XDVDFS Directory Padding Fix & Native Android CI Rebuild

### What Changed & Why

* **XDVDFS 16-Bit Directory Padding Fix (`src/ImageReader/ImageReader.cpp`)**:
  * **Change**: Updated the directory table padding check in `ImageReader::populate_directory_entries()` from `read_entry.header.left_offset == Xiso::PAD_BYTE` (`0x00FF`) to `read_entry.header.left_offset == Xiso::PAD_SHORT` (`0xFFFF`).
  * **Why**: In the XDVDFS (XISO) specification, `left_offset` is a 16-bit (`uint16_t`) 4-byte word offset, while unused sector tail padding is filled with `0xFF` bytes (resulting in `0xFFFF` for a 16-bit field). Comparing a 16-bit offset against the 8-bit `PAD_BYTE` (`0x00FF`) caused valid directory entries pointing to word offset `0x00FF` (`1020` bytes into a directory table) to be mistaken for sector padding. As a result, that entry and its entire child subtree were silently skipped during ZAR/image conversion or extraction (discovered during a ZAR conversion of *Mobile Suit Gundam: Operation Troy*, where 6 shader files were omitted, causing a disc-read error).
  * **Note on Existing Archives**: Any ZAR or disc image previously generated from a disc containing a `0x00FF` directory offset should be recreated from the original source image.

* **Automated Directory Traversal Regression Suite (`tests/`)**:
  * Added 7 CTest regression cases compiling the production `ImageReader` traversal methods against synthetic XDVDFS trees (`0x00FF` valid subtree retention, `0xFFFF` padding rejection, nested subdirectories, `executable_entry()` lookup, and partition offsets).

* **Android Native Core CI Compilation (`tools/build_android_native.sh`, `android/jni/CMakeLists.txt`)**:
  * Release builds now compile and strip `libxgdtool.so` (`arm64-v8a`) directly from the current C++ source tree in CI and verify the packaged library SHA-256 inside `XGDTool-Android.apk`.

* **Release Packaging & Notes (`.github/workflows/release.yml`)**:
  * GitHub Releases now publish structured release notes directly from `docs/releases/<tag>.md` alongside standalone Windows, Linux (`x86_64` / `aarch64`), and Android binaries.
